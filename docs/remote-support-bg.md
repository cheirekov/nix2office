# Предложение за отдалечена графична поддръжка

За съществуващите ваши hbbs/hbbr сървъри RustDesk е естественият избор. Запазваме SSH за административна работа и добавяме RustDesk за помощ върху видимия desktop. XFCE използва Xorg; поведението при заключен екран, излизане от сесията и преди login трябва да се провери на реалната машина.

Това е предложение; RustDesk и нов отдалечен достъп още не са включени в конфигурацията.

## Предложен избор в помощника

- Изключено по подразбиране.
- Поддръжка със съгласие: клиент в потребителската сесия, потребителят приема връзката.
- Достъп без присъствие: отделна изрична настройка, със защитено удостоверяване и отделна проверка на работа след reboot/login.

Планирани полета в локалния `machine.toml`: режим, ID server (hbbs), relay server (hbbr), публичен server key. Няма нужда от RustDesk server на офис машината. hbbs е сървърът за идентификация/установяване на връзката, а hbbr препредава трафика при нужда. Това е различно от настройката за HTTP/SOCKS proxy.

Публичният server key се взема от `id_ed25519.pub` на hbbs; частният му ключ не се копира на клиентите. Парола за достъп без присъствие не се записва в TOML, Git или Nix store: механизмът за подаването ѝ трябва да се провери и да използва SOPS или защитен runtime файл. API server е за съответните Pro възможности и не е необходим за обикновения OSS сценарий.

## Реализация в следващ етап

1. Избор на подходящия RustDesk клиент от фиксирания nixpkgs, пакет и потребителско стартиране.
2. Декларативно подаване на адресите и публичния server key, съобразено с поддържания от клиента формат и личните му настройки.
3. Проба на входяща връзка през вашите сървъри, съгласие и прекъсване, после отделно unattended режим, ако е нужен.
4. Проверка на действително необходимите мрежови правила, без автоматично отваряне на server портовете на всички офис машини.

Официална документация: [настройка на клиента](https://rustdesk.com/docs/en/self-host/client-configuration/), [Linux клиент](https://rustdesk.com/docs/en/client/linux/).
